# AGENTS.md

## Project

SMS Guardian classifies a pasted text message as `spam` or `ham`. The FastAPI backend loads `backend/message_classifier.joblib` and exposes `/health` and `/predict`. The Next.js frontend proxies requests through `/api/predict` and `/api/health` to `BACKEND_URL`.

## Layout

- `backend/` contains the FastAPI service, Python requirements, Dockerfile, and the model copy used at runtime.
- `frontend/` contains the Next.js 16 App Router app. Read `frontend/AGENTS.md` before changing frontend code.
- `sms-message-classifier.ipynb` assembles the dataset and trains the model.
- `message_classifier.joblib` is the root model artifact. Keep it identical to `backend/message_classifier.joblib`.
- `.github/PULL_REQUEST_TEMPLATE.md` is the pull request checklist.
- `README.md` documents setup, the API, and the dataset.

## Commands

Install dependencies from the repo root:

```
npm install
npm --prefix frontend install
pip install -r backend/requirements-dev.txt
```

Run checks:

```
npm run lint
npm run typecheck:frontend
npm run build:frontend
```

Start the backend:

```
uvicorn main:app --app-dir backend --reload --port 8000
```

Start the frontend:

```
npm --prefix frontend run dev
```

Start both with Docker:

```
docker compose up --build
```

## Conventions

- Branch from `main` with `<type>/<short-description>`, for example `feat/frontend-confidence-warning` or `fix/backend-empty-text`. Use lowercase and hyphens, not spaces.
- Allowed types are `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`, and `revert`.
- Commit messages must match `<type>: <message>`. The Husky hook runs `scripts/check-commit-msg.js`, so a message such as `fix: handle whitespace-only messages` passes and `fixed stuff` does not.
- Keep a pull request scoped to one area. Complete `.github/PULL_REQUEST_TEMPLATE.md` and include screenshots for UI changes.
- Run the checks before handing off work.
- Do not commit unless the user asks.
- Update `README.md` when endpoints, environment variables, commands, or model behavior change.

## Model and data

- Training uses only `ham` rows from the UCI SMS Spam Collection and only `spam` rows from the Philippine dataset. The README lists the row counts and test metrics.
- The notebook writes `spam_classifier.joblib`. The runtime expects `message_classifier.joblib`.
- If you retrain, update the notebook, record the metrics, rename the output, and replace both model copies.
- Do not log or persist message text. Keep it in memory only.
